# Parity matrix

Legend: done, partial, planned, n/a (platform does not need it).

| Area | macOS | Windows | Notes |
| --- | --- | --- | --- |
| Release packaging | Xcode Cloud: signed, notarized DMG | partial | Windows: unsigned zip, per-user installer and `SHA256SUMS-windows.txt` via `windows-release.ps1`; GitHub Actions draft release on tags. Zip and installer smoke-tested locally; clean-VM install and the first CI run are not done |
| Document load/save, BOM, line endings | done | partial | Windows: vectors in `spec/vectors` |
| Atomic save + transaction manifest | done | done | Windows: manifest, then `ReplaceFileW` with the old file kept as a displaced sibling (macOS keeps it in the temp slot). No directory fsync on Windows. Vector: `atomic-write-recovery.json` |
| Crash recovery journal | done | done | JSON records under `%LOCALAPPDATA%ClioCrash Recovery`; vector: `recovery-journal.json`. Called by `DocumentService` (checkpoints before every write, clear after) and `StartupRecovery`; wired into the app (every edit journaled, startup sweep) |
| Document identity store | done | partial | Core store ported (file id from `FILE_ID_INFO`, case-folded locators); vector: `document-identity.json`. Used by `WorkspaceScanner.ScanFiles` and the search index |
| Move transactions + `DocumentMover` | done | done | Manifest, quarantine and recovery (`move-recovery.json`); `DocumentMover` drives them with collision choices, replace approval, identity migration and Recycle Bin delete (`document-move.json`). Buffer settling and displaced-buffer recovery stay with the caller. Not wired into the app yet |
| Safe file names | done | done | Windows adds reserved names, illegal characters, trailing dots, 255 cap; vector: `file-names.json` |
| Revision digest (SHA-256) | done | partial | Same vectors |
| Workspace scan + .gitignore | done | partial | `ScanFiles` adds stable ids via the identity store; optional `.txt` support. No discovery policy, built-in exclusions or ignored-file tier yet |
| External-edit conflicts, autosave, startup recovery | done | done | `DocumentSession` + `DocumentService` (save, reconcile, resolve, deletion), `Autosaver` (400 ms debounce, one write at a time, journal on every edit), `StartupRecovery`; vector `external-change.json`. Unbacked documents are journaled but not written (the app picks a location). Wired into `Clio.App`: one session and autosaver per open document, banner plus version-choice dialog for conflicts, banner for deleted files, Save As for detached text |
| Workspace watcher | done (FSEvents) | done | Windows: `FileSystemWatcher` (ReadDirectoryChangesW) + 200 ms root liveness timer + snapshot diff (`workspace-snapshot-diff.json`); deletions confirmed after 120 ms because swap-style saves briefly remove the path. Wired into `Clio.App`: one watcher per folder, batches go to the search index, then to open documents (reconcile) and the sidebar tree |
| Search index (SQLite FTS5) | done | partial | Windows: `SearchIndex` on `Microsoft.Data.Sqlite`, 500-match cap, progressive batches; vector `search-queries.json`. Not yet ported: ignored-file tier and discovery policy; text files off by default |
| Recovery copies, 7 days | done | done | `RecoveryStore` ported, vector `recovery-store.json`; used by `DocumentMover`, `DocumentService.Resolve` and `StartupRecovery` |
| Editor: focus, typewriter, minimap, selection, undo | done | partial | Windows: `Clio.Editor` logic + Win2D `EditorControl`; shares `focus-ranges.json` |
| Editor: Markdown highlighting (Full and Reduced modes) | done | partial | Windows: lexer ported, Markdig for emphasis/strong/strikethrough; shares `markdown-highlight.json`, which the macOS suite does not read yet. No safe-large-file semantic chunking; Foundation line separators (U+2028/2029/0085) are not line breaks |
| Editor: incremental re-highlight | done | done | Windows: IncrementalHighlighter, always equal to a full highlight (seeded fuzz over the conformance fixtures). Deviations from the macOS policy, which cannot see them: fences, front matter and footnotes spanning blank lines, indented islands, edits in leading whitespace, link reference definitions and ~ all force a full reparse. The macOS policy has the same blind spots |
| Editor: IME composition | done | partial | Windows: proxy `TextBox` inside `EditorControl`, not `CoreTextEditContext`. No Windows App SDK package ships a window-based text service (`Microsoft.UI.Text.Core`), and the Windows SDK type needs a CoreWindow; a window-handle interop entry exists in the SDK but its header is not available to port from. Not yet tested with a real IME |
| Editor: slash commands and command palette | done | partial | Windows: logic in `Clio.Editor.Commands`, vector `slash-commands.json` (the macOS suite does not read it yet). Ctrl+K and a typed `/` open the palette. Wired commands: new, open, search, rename, delete, reveal, folder, focus, typewriter, sidebar, settings. export waits for phase 4 |
| Editor: UI Automation | done | partial | Windows: Document element with a Text pattern (units, move, endpoints, find, select, point and rectangles) served by the IME proxy peer; checked against a live UIA client. No text attributes beyond font name and read-only, no ITextEditProvider, not tried with Narrator |
| Editor: high contrast | done | partial | Windows: system colours, hue-coded roles collapse to text colour, links underlined, selection uses highlight text. Polled every 1.5 s because the high-contrast change event cannot be subscribed to unpackaged. Not seen under a real high-contrast theme |
| Export PDF/HTML/DOCX/TXT | done | partial | Windows: `Clio.Export` (UI-free API, `DocumentExporter`), shares `export-policy.json` (the macOS suite does not read it yet). Markdig supplies the model, so footnote definitions sit at the end of the document and unusual constructs may parse differently from swift-markdown. PDF uses PDFsharp/MigraDoc: real tables and clickable safe links, but strikethrough is shown as muted ~~text~~ and emoji and symbols outside Segoe UI fall back to missing-glyph boxes. `/export` is wired in the app: an options sheet (format, and inline paper, orientation and margin choices in place of the macOS page-layout panel), the save picker, Cancel, keep-both/replace on a collision and Retry on failure; `/export <format>` skips the sheet. Recovery-checkpoint directory transactions for exports are not ported; collisions use `AtomicFile` create/replace-if-revision. Driven through UI Automation on the Release build (PDF and plain text); generated PDF and Word files were not opened in a viewer or Word |
| Workspace UX: sidebar tree, open documents, multiple windows | done | partial | Windows: identity-based scan tree, OPEN DOCUMENTS list as the tab strip, Ctrl+Tab, Ctrl+W, Ctrl+Shift+N windows; a file open in another window activates that window. Not yet: drag-and-drop moves (use Move to folder), single-instance activation for files opened from Explorer |
| Workspace UX: new, rename, move, delete | done | partial | Windows: file picker for new and Save As, rename and move through `DocumentMover` with keep-both/replace approval (replaced open text goes to recovery), delete to the Recycle Bin after a revision check. Tree actions open the document first, then act on it |
| Search UI: quick open and workspace search | done | done | Windows: Ctrl+P filename quick open, Ctrl+Shift+F or /search full text, progressive batches, 500-match cap with a notice |
| Markdown file association | done | partial | Windows: opt-in toggle registers Clio under "Open with" for .md and .markdown in HKCU (no admin); the default-app choice stays with the user in Windows Settings. Not exercised end to end |
| Local MCP | done | partial | Windows: `Clio.Mcp` (policy, HTTP listener, router, tools, Credential Manager, client config) and `clio-mcp-bridge.exe` are done and tested against `mcp-access.json` and `mcp-protocol.json`; the app still has to implement `IMcpHost`, the tray toggle, settings page and login autostart. macOS tests do not read the vectors yet. Windows ids are upper-case dashed GUIDs like macOS; the Windows listener also sets exclusive address use and drops non-loopback peers |
| Undo history per document | done | done | Windows: each tab keeps its own text, selection, undo history and scroll position; showing a tab again resumes where it was. A document reloaded after an outside edit starts a fresh history |
| Keyboard shortcuts and focus | done | partial | Windows: Ctrl+, (Settings) and Ctrl+Tab / Ctrl+Shift+Tab are handled by a tunnelling key handler on the window because WinUI 3 does not deliver punctuation or Tab accelerators while a text box has focus. The editor takes focus on launch, and returns to it after the palette, the export sheet and Settings close. Checked through UI Automation |
| Window size at display scale | n/a | partial | Windows: window sizes are in device-independent pixels and scaled by the display's DPI, kept inside the work area (`WindowSizing`, unit-tested). Only seen at 100% scaling, which is this machine's setting |
| Assisted commands / paste formatting | done | partial | Windows: `Clio.Intelligence` (UI-free). Shares `intelligence-command-intent.json`, `intelligence-structure-recovery.json` and `intelligence-transport.json` (the macOS suite does not read them yet). Off by default; the key lives only in Credential Manager (`olympus.clio.windows.typesafe`, this device, never in settings or logs); the only network code is `TypeSafeClient` (HTTPS only, no redirects, key only in the Authorization header). Platform differences: palette descriptions say Recycle Bin and File Explorer; a CRLF pair counts as one line break when reading a paste (macOS sees two). Unit-tested over a fake HTTP handler and the real Credential Manager. Driven through UI Automation with the feature off (palette finds nothing, paste lands untouched and undoes in one step) and for the Settings key flow; the assisted palette match and paste reformatting against the live service were not exercised, because that would send text to a third party |
